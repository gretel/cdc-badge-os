## Summary
The `compile_commands.json` file (generated by CMake) contains a complete JSON database of all compile commands used to build the project. This file exposes:
- Full absolute paths to source files
- Include search paths
- Compiler flags and definitions
- ESP-IDF installation path
- PlatformIO environment structure

If this file is generated and shared, it reveals the complete build environment structure.

## Impact
- **Path disclosure**: Full filesystem paths revealed (e.g., `/home/user/.platformio/penv/...`)
- **Dependency fingerprinting**: Exact ESP-IDF version and configuration
- **Build reproducibility**: Attackers can recreate exact build environment
- **Structure exposure**: All source files and their dependencies are enumerated

## Evidence
File: `.pio/build/cdc_badge_usb/compile_commands.json` (when generated) contains entries like:
```json
{
  "directory": "/input/20260423-132359-oj8ayc/cdc-badge-os/.pio/build/cdc_badge_usb",
  "command": "/path/to/xtensa-esp32s3-elf-gcc ... -I/input/.../components/... -DDEBUG_MODE=1 ...",
  "file": "/input/20260423-132359-oj8ayc/cdc-badge-os/components/.../src/..."
}
```

The file is generated by CMake when using the `-DCMAKE_EXPORT_COMPILE_COMMANDS=1` flag or via PlatformIO's `build_type = debug`.

## Recommended Fix
1. Add `compile_commands.json` to `.gitignore` (or `.pio/` entire directory)
2. Document that this file should not be shared outside development team
3. Consider using symlink approach: `ln -s .pio/build/cdc_badge_usb/compile_commands.json` for IDEs
4. Review `.gitignore` to ensure build artifacts are properly excluded

Example `.gitignore` entry:
```
# Build artifacts
.pio/
build/
compile_commands.json
```
