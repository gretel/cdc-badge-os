## Summary
The VS Code C/C++ properties file (`.vscode/c_cpp_properties.json`) contains hardcoded absolute paths specific to the original developer's machine (`/Users/krim/GIT/cdc-badge-os/`). This makes the workspace settings non-portable for other developers.

**Location:** `.vscode/c_cpp_properties.json` (lines 11-494)

## Impact
- **Poor developer experience**: Other developers cloning the repo will have broken IntelliSense until they manually update paths
- **Commit noise**: Developers may accidentally commit path changes specific to their machine
- **Onboarding friction**: New contributors need to know to update VS Code settings manually

## Evidence
File: `.vscode/c_cpp_properties.json`
```json
{
    "configurations": [
        {
            "name": "PlatformIO",
            "includePath": [
                "/Users/krim/GIT/cdc-badge-os/main",           // Line 11 - hardcoded
                "/Users/krim/GIT/cdc-badge-os/include",        // Line 12 - hardcoded
                "/Users/krim/.platformio/packages/...",        // Line 13 - hardcoded
                // ... 480+ more lines with /Users/krim paths
            ],
```

The file header even warns:
```json
//
// !!! WARNING !!! AUTO-GENERATED FILE!
// PLEASE DO NOT MODIFY IT AND USE "platformio.ini":
// https://docs.platformio.org/page/projectconf/section_env_build.html#build-flags
//
```

## Recommended Fix
1. Replace hardcoded paths with `${workspaceFolder}` variable:
   ```json
   "includePath": [
       "${workspaceFolder}/main",
       "${workspaceFolder}/include",
       // PlatformIO will populate the rest automatically
   ],
   ```

2. Since the file is auto-generated by PlatformIO, consider:
   - Adding `.vscode/c_cpp_properties.json` to `.gitignore`
   - Or keeping a minimal template with relative paths

3. Document in `README.md` that PlatformIO auto-generates these settings
