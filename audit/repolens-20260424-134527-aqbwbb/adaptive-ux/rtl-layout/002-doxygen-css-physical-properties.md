## Summary
The Doxygen-generated documentation CSS (`doxygen_output/html/doxygen.css`) extensively uses physical directional properties that will break in RTL layouts:

**Key occurrences (lines):**
- Line 459: `margin-right: 15px;`
- Line 522-524: `margin-right: 6px; padding-right: 6px; text-align: right;`
- Line 534-540: `padding-right: 6px; padding-left: 6px;`
- Line 579: `margin-left: 50px;`
- Line 666: `padding-left: 10px;`
- Line 672: `margin-left: -1cm;`
- Line 677: `padding-left: 40px;`
- Line 687: `left: -18px;`
- Line 735: `text-align: left;`
- Line 765: `right: 5px;`
- Line 814: `padding-left: 62px;`

## Impact
When viewing documentation with `dir="rtl"`:
- Navigation trees and indented content will have wrong indentation direction
- Tables and member lists will have misaligned columns
- Positioning with `left:`/`right:` will flip incorrectly
- Text alignment will be wrong for mixed LTR/RTL content (code, identifiers)

## Evidence
Sample from doxygen.css:
```css
/* Line 522-524 */
.memItemLeft {
  margin-right: 15px;
  text-align: right;  /* Should be end for RTL */
}

/* Line 579 */
.groupheader {
  margin-left: 50px;  /* Should use margin-inline-start */
}

/* Line 687 */
.treetv {
  left: -18px;  /* Should use inset-inline-start */
}

/* Line 735 */
td.key {
  text-align: left;  /* Should be start */
}
```

## Recommended Fix
Replace physical properties with logical equivalents throughout `doxygen.css`:

| Physical Property | Logical Equivalent |
|-------------------|-------------------|
| `margin-left` | `margin-inline-start` |
| `margin-right` | `margin-inline-end` |
| `padding-left` | `padding-inline-start` |
| `padding-right` | `padding-inline-end` |
| `text-align: left` | `text-align: start` |
| `text-align: right` | `text-align: end` |
| `left:` | `inset-inline-start:` |
| `right:` | `inset-inline-end:` |

**Note:** Since this is auto-generated by Doxygen, consider:
1. Creating a custom CSS override file that patches these properties
2. Configuring Doxygen to use a custom stylesheet with logical properties
3. Adding a post-processing step to convert physical to logical properties
